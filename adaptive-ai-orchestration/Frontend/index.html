Project overview

Making an AI request path visible.

A visitor asks a general question or a question about Sankalpa. The system uses transparent rules to choose a direct model route or a document-grounded RAG route, then exposes the decision and result.

01 / Input

A question

Visitors provide a short question. No account is required for this public demo.

02 / Processing

Route, retrieve, respond

Rules classify intent and complexity. Sankalpa/handbook queries retrieve relevant PDF passages before a response is returned.

    Possible failure cases

    The API can reject unsafe input, abstain when no support is found, return a structured service error when a model or dependency fails, or show evaluation as pending or skipped.

    Why this is useful for learning

    The visible trace makes it easier to discuss routing trade-offs, grounded answers, latency, model fallback, and where a real production system needs stronger controls.

    FAISS + embeddings

    FAISS provides local vector search over the small fictional handbook. It is suitable for this demo but lacks managed scaling and incremental indexing.

    PostgreSQL + Streamlit

    PostgreSQL records requests and evaluation metadata. A separate Streamlit dashboard reads aggregate API metrics for exploration.

    Algorithms & rules

    What the scores actually mean.

    The project uses heuristics and a lightweight routing score. They are implementation choices, not claims of calibrated AI intelligence.

    Vector similarity

    cosine(A, B) = (A · B) / (||A|| × ||B||)

    A and B are normalized embedding vectors for the question and a PDF chunk. FAISS uses inner product after normalization, which equals cosine similarity. Example: 0.80 ranks above 0.45. Implemented in RAG/vector_store.py.

    Hybrid reranking

    final = 0.7 × vector_score + 0.3 × lexical_overlap

    Lexical overlap is the fraction of meaningful query terms found in a chunk. For vector score 0.60 and overlap 0.50, final score is 0.57. This helps precise policy terms, but it is not a cross-encoder reranker.

    Model routing utility

    utility = wq × quality − wl × latency − wc × cost

    Weights change with complexity: low (0.2, 0.4, 0.4), medium (0.5, 0.3, 0.2), high (0.8, 0.15, 0.05). Adaptive routing uses this only after all model/complexity records exist; otherwise it uses a static capability baseline.

    Evidence constraint

    RAG answers must contain one or two exact, cited source passages. The app rejects invented quotes, source IDs outside retrieval context, question-shaped “answers,” and evidence over the compact character budget.

    RAG/evidence.py

    Fictional data source

    The Sankalpa handbook is synthetic by design.

    It was created for this educational simulation and contains no real-company confidential information. The RAG pipeline extracts PDF text page by page, splits it into 500-character chunks with 50-character overlap, embeds them with Amazon Titan Text Embeddings V2, and stores vectors in FAISS.

    Before you try it

    • Use sample or non-sensitive information only.
    • Do not enter passwords, personal data, or private company documents.
    • Expect occasional inaccurate, incomplete, or irrelevant results.
    • Try questions outside the handbook and ambiguous prompts.
    • Report issues so the project can improve.

    Limitations & roadmap

    Useful, but intentionally not presented as production-ready.

    Current limitations

    • Intent and complexity are rule-based heuristics, not trained classifiers.
    • RAG can retrieve irrelevant passages; its fallback uses lexical matching.
    • The index rebuilds the entire handbook rather than updating incrementally.
    • LLM-based quality judging is not independent human ground truth.
    • Public-demo endpoints are intentionally unauthenticated and should stay on a trusted deployment boundary.

    Roadmap

    Working direct routing, RAG retrieval, sources, usage records, optional evaluation.

    Needs improvement retrieval relevance, error observability, deployment controls, and accessibility testing.

    Planned authenticated access and document-level permissions for private deployments.

    Long-term human-labelled evaluation, incremental indexing, and a stronger semantic reranker.

    Cold-start note. This is not a recommendation system, so it has no user/item preference data and does not implement traditional new-user or new-item cold-start handling. For a new routing system, it starts with static complexity-to-model baselines until the adaptive policy has complete recorded model data.
